- Se hizo que el workflow falle (`exit code 1`) si no se publica ninguna publicación.

## ❌ Errores encontrados y cómo se corrigieron

### Error 1: Token expirado
**Mensaje:** `Session has expired on Wednesday, 19-Aug-26 00:00:00 PDT`
**Causa:** El token anterior había caducado.
**Solución:** Se generó un nuevo Page Access Token de larga duración y se actualizó en GitHub Secrets.

### Error 2: `publish_actions` deprecado
**Mensaje:** `(#200) The permission(s) publish_actions are not available. It has been deprecated.`
**Causa:** Se estaba usando un **User Access Token** en lugar de un **Page Access Token**.
**Solución:** Se obtuvo el token correcto desde `me/accounts?fields=name,access_token,tasks` en Graph API Explorer.

### Error 3: Workflow ejecutaba commit antiguo
**Síntoma:** El log mostraba `commit = 253b9ef...` en lugar del commit actual.
**Causa:** Se usaba "Re-run jobs" en ejecuciones anteriores.
**Solución:** Se instruyó ejecutar siempre con **Run workflow** → **Branch: main** para usar el código más reciente.

### Error 4: `--validate` no reconocido
**Mensaje:** `run_automation.py: error: unrecognized arguments: --validate`
**Causa:** Se agregó la lógica de `--validate` pero no se registró el argumento en `argparse`.
**Solución:** Se agregó `parser.add_argument("--validate", ...)`.

### Error 5: Workflow no fallaba cuando no publicaba
**Síntoma:** Aunque no se publicaba nada, el job terminaba como exitoso.
**Causa:** Faltaba `sys.exit(1)` en la ruta principal `run_posts()`.
**Solución:** Se agregó `sys.exit(1)` cuando `success == 0` y hay posts programados.

### Error 6: Zona horaria UTC causaba día equivocado
**Síntoma:** La ejecución vespertina podría usar el día siguiente en UTC.
**Causa:** El script usaba `datetime.now()` del servidor (UTC en GitHub Actions).
**Solución:** Se cambió a `datetime.now(ZoneInfo("America/Mexico_City"))` y se agregó `tzdata` a las dependencias.
